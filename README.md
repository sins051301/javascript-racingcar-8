# javascript-racingcar-precourse

## 목표
초간단 자동차 경주 게임을 구현한다.

## 요구사항
- 주어진 횟수 동안 n대의 자동차는 전진 또는 멈출 수 있다.
- 각 자동차에 이름을 부여할 수 있다. 전진하는 자동차를 출력할 때 자동차 이름을 같이 출력한다.
- 자동차 이름은 쉼표(,)를 기준으로 구분하며 이름은 5자 이하만 가능하다.
- 사용자는 몇 번의 이동을 할 것인지를 입력할 수 있어야 한다.
- 전진하는 조건은 0에서 9 사이에서 무작위 값을 구한 후 무작위 값이 4 이상일 경우이다.
- 자동차 경주 게임을 완료한 후 누가 우승했는지를 알려준다. 우승자는 한 명 이상일 수 있다.
- 우승자가 여러 명일 경우 쉼표(,)를 이용하여 구분한다.
- 사용자가 잘못된 값을 입력할 경우 "[ERROR]"로 시작하는 메시지와 함께 Error를 발생시킨 후 애플리케이션은 종료되어야 한다.

- [x] 자동차 class 만들기
- [x] 자동차 내부 move 함수 구현 (position 증가)
- [x] 자동차 내부 getTrack 함수 구현 (position만큼 "-" 반환)
- [x] 자동차 이름 구분 받아 저장하기
- [x] 자동차 이름은 5글자 이하로 제한하기 
- [x] 사용자는 몇 번의 이동을 할 것인지를 입력 받기
- [x] 이동 입력에 대한 검증
- [x] 자동차 경주 실행 함수 구현 (이동 입력값만큼 자동차 이동)
- [x] 자동차 경주 우승자 함수 구현
- [x] 각 함수에 대해 테스트 코드 작성



## 추가로 생각해 본 부분

### 자동차의 각 상태를 어떻게 저장할 것인가?
- 여러 자동차 인스턴스를 동일한 규칙으로 관리하기 위해 class를 사용하였다.
- 상태(state)와 행동(behavior)을 함께 가지기 때문에 class를 사용하였다.

### 사용자가 입력에 따른 오류를 어떻게 처리할 것인가?
    - 1. 사용자가 입력을 다한 뒤 오류를 낼 경우
    - 2. 사용자가 입력을 다하지 않은 상태에서 오류를 낼 경우
- 2번을 선택하였다. 사용자가 입력을 다한 뒤 오류를 내는 것은 사용자 친화적이지 못하다고 판단하였다.

### 동명이인을 경우에는 어떻게 처리할 것인가?
    - 1. 동명이인을 입력할 경우 Error를 발생시킨다.
    - 2. 동명이인을 입력할 경우 동명이인을 구분하여 출력한다.
- 2번을 선택하였다. 1번 방법보다는 2번이 더 생각할 것이 많다고 판단하였다.  

### 자동차 경주 함수의 내부 함수를 파일로 분리할 것인가?
- 서로 연관되어 있는 함수이기 때문에 한 파일에 작성하였다.

### 각 파일들을 폴더로 분리할 것인가? 분리한다면 어떻게 분리할 것인가?
- 프로젝트의 구조를 입력(input) · 실행(race) · 결과(result) 단계로 나누었다.
  이는 코드의 관심사(Separation of Concerns) 를 명확히 분리하기 위함이다.
  또한 이 정도 규모의 프로젝트에서는 MVC 패턴을 적용하기보다는,
  역할별 단계로 나누어 구조를 단순화하는 방식이 더 적합하다고 판단하였다.

    - 1. 입력(input): 사용자 입력과 검증 로직을 담당한다.
    - 2. 실행(race): 실제 경주 로직과 자동차의 이동을 담당한다.
    - 3. 결과(result): 우승자 계산 및 결과 출력을 담당한다.
